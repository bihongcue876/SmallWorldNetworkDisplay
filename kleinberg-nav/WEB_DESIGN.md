# 前端工作逻辑设计

本文档定义浏览器演示的布局、状态、数据流与交互。实现时以 [Theory.md](Theory.md) 的模型口径为准；前端只负责参数、渲染与结果展示，算法全部来自 `src/core`。

## 1. 目标与边界

目标：让“短路径存在但找不到”这件事可见。用户能调参、看单次路由动画、跑小批量实验、导出结果。

边界：单页静态应用，无后端、无账号、无数据库；只实现 Kleinberg 一个模型；`k` 首版固定为 1。

## 2. 技术栈

- Vite + TypeScript 的 vanilla 模板，不引入 React。
- Canvas 2D 绘制网络与路径。
- Web Worker 跑批量实验，避免主线程冻结。
- 图表自绘，不引入重型可视化库。

## 3. 页面布局

```
┌──────────────────────────────────────────────────────────────┐
│ kleinberg-nav      [单次演示] [批量实验]    预设: α=0 1 2 3  │
├───────────────┬──────────────────────────────┬───────────────┤
│ 参数           │ Canvas                        │ 指标           │
│ n     [32 ▾]  │  网格、长程边、路由路径        │ 跳数 T         │
│ α     [2.00]  │                               │ 最短路 ℓ       │
│ seed [42][随机]│ 播放 ▶  暂停 ⏸  单步 →       │ 效率比         │
│ [重建] [截图]  │  速度 ———●———                │ 长程边使用率   │
├───────────────┴──────────────┬────────────────────────────────┤
│ 批量视图：切到“批量实验”时，画布与指标卡隐藏，│                │
│ 结果表占中间整栏，限高滚动、表头固定          │                │
└──────────────────────────────────────────────┴────────────────┘
```

- 左栏宽 280px，右栏宽 300px，中间自适应。
- 批量视图下结果表限高滚动，多组结果不互相遮挡、不撑破页面。
- 窄屏时左右栏堆叠到画布下方，不做移动端专门优化。

### 3.1 页面说明

页头右侧放“说明”按钮，点开是覆盖画布上方的浮层，宽 520px，带遮罩；首次进入自动展开一次，关闭后状态存 `localStorage`，不再自动弹出。文案写死在 `src/web/about.ts`，不进模板字符串拼接，便于直接修改和校对。

浮层内容分四段，每段一个短标题加两三句话，全部用界面上的同一套词：

1. **这是什么**：n×n 环面网格，每个节点连四个邻居，另有一条按距离幂律抽出的长程边。α 表示这条边的距离偏好，α 小则到处乱指，α 大则只指向近处。
2. **怎么走**：从 s 到 t，每一步只看当前节点的邻居与目标位置，走向离目标更近的那个节点，不回头、不搜索、不预知全局。
3. **怎么看图**：橙色是实际走出的路径，灰色细线是其他节点用不上的长程边，红圈是卡住的节点，虚线圆是目标邻域。α=2 时每步大约把距离减半，α=0 时容易在离目标很远的地方停住。
4. **怎么读指标**：右侧数字是多次抽样后的统计量。成功率与效率比要一起看，因为平均跳数只统计成功的那些次；标注“示例，不作为统计结论”的四个预设只用于直观对比。

浮层底部固定一行免责说明：本页只模拟 Kleinberg 模型，结论不直接外推到真实社交网络。四个案例全部由同一随机种子生成，切换 α 时 s 与 t 不变。

## 4. 状态模型

```ts
type Mode = 'demo' | 'batch';
type Status = 'idle' | 'building' | 'routing' | 'done' | 'error';

interface AppState {
  mode: Mode;
  status: Status;
  config: ExperimentConfig;   // n, alpha, k, graphs, pairs, seed, stepLimitFactor
  graph: Graph | null;
  route: RouteResult | null;  // 单次演示
  batch: BatchResult | null;  // 批量结果
  playing: boolean;
  cursor: number;             // 动画当前走到第几步
  speed: number;              // 每秒步数
  message: string;
}
```

状态只通过动作修改：`setConfig`、`rebuild`、`runOnce`、`play`、`pause`、`step`、`reset`、`runBatch`、`cancelBatch`、`exportCsv`。

## 5. 数据流

```
参数面板 → 校验 → 建图（带缓存）→ 单次路由 / 批量
                                      ↓
                                 指标计算
                                      ↓
                             Canvas 渲染 + 指标卡 + 图表
```

- 单次演示：建图后立刻对当前 s、t 跑一次路由，结果存在 `route`，动画只播放已算好的 `path`。
- 批量实验：参数与单次共用，增加 `graphs`、`pairs`；交给 Worker。
- 任何参数变化都把 `status` 置为 `idle`，并取消正在播放的动画。

## 6. 模块划分

```
src/core/        纯算法，无 DOM：types, rng, distance, graph, sample, route, metrics, experiment
src/worker/      experiment.worker.ts：接收配置，返回进度与结果
src/web/main.ts  入口，绑定 DOM 事件
src/web/state.ts 状态与订阅
src/web/panels.ts 参数面板、指标卡、案例按钮
src/web/render.ts Canvas 绘制
src/web/charts.ts α 曲线、相图
src/web/format.ts 数字与百分比格式化
```

前端不得直接实现距离、采样或路由；所有计算调用 `src/core`。

## 7. 交互设计

- 画布点击：把最近的节点设为起点；按住 Shift 点击设为终点。
- n 下拉：16、32、48、64、80、96、112、128，默认 32。
- α 滑块：0 到 4，步长 0.25，默认 2；拖动时防抖 200ms 重建。
- k 输入：首版固定 1，禁用编辑，保留位置。
- seed 输入：整数，默认 42；修改后重建并重置动画。“随机”按钮用 `crypto.getRandomValues` 生成一个种子并重建，供自由探索；种子会显示在输入框里，可复制复现。
- 截图按钮：把当前画布导出为 PNG，文件名含 n、α 与 seed，便于写论文或报告时引用。
- 重建按钮：清空缓存，按当前参数重新生成图与路由。
- 播放控制：播放、暂停、单步、重置；速度 1 到 30 步每秒。
- 预设案例：α=0、1、2、3 四个按钮，切到单次模式并加载固定参数。
- 批量：开始、取消、进度条、结果表、导出 CSV。
- 状态栏：显示“建图中”“第 7/12 步”“已取消”“出错”等。

## 8. 演示案例

四个案例共用 `seed=42`、同一对 s、t（按 n 比例取，例如 n=32 时 s=(2,2)、t=(29,27)），便于并排比较。

| 案例 | α | 预期 |
|---|---|---|
| 随机长程边 | 0 | 频繁 dead-end，路径走不远 |
| 偏长 | 1 | 远离目标时跳得快，接近目标时缺跳板 |
| 最优 | 2 | 每步距离大约减半，成功 |
| 偏短 | 3 | 长程边太短，路径逐格爬行 |

每个案例在指标卡下方标注“示例，不作为统计结论”。案例参数写在 `src/web/cases.ts`，不散落在事件处理里。

指标卡在平均跳数下方显示同一对 `s`、`t` 的最短路跳数 `ℓ` 作为对照；效率比 `T / ℓ` 只在成功时才有定义，失败案例显示“—”。

## 9. 批量实验

- 前端默认小样本：`graphs = 5`、`pairs = 20`，保证几十秒内出结果。
- 结果表按 `configHash` 累积：同一配置再跑一次替换原行，不同配置（如 α=0 与 α=2 各跑一次）各占一行，便于横向对比。
- “论文网格”按钮填入完整网格：n 取 16 到 128 每隔 16，α 取 0 到 3 步长 0.25；提示全量应改用 Node 脚本。
- Worker 每完成一个配置发一次进度，主线程更新进度条与结果表。
- 结果表列：n、α、样本量、成功率、平均跳数、最短路、效率比、长程边使用率。
- 导出 CSV 时附带 seed 与 configHash。
- 取消：terminate 当前 Worker 并立即重建一个空闲 Worker；批量随 terminate 即时停止，不残留计算。

## 10. 随机数与可复现

- 伪随机数用 mulberry32，实现在 `src/core/rng.ts`。
- 派生规则：`deriveSeed(base, purpose, index)`，`purpose` 取 `graph`、`pair`、`tie`，`index` 为图序号或对序号。
- 建图、抽源目标、平局使用独立流，互不干扰。
- 禁止 `Math.random()`。
- 指标卡显示当前 seed；导出的 CSV 第一列是 configHash。

## 11. 渲染策略

绘制顺序：网格线 → 本地边 → 长程边 → 路径 → 节点 → 标签。

- n 不超过 64：画全部节点、本地边与长程边。
- n 大于 64：只画长程边与路径，节点按 2×2 抽样绘制，避免卡顿。
- 长程边按长度着色：短边偏蓝，长边偏红，透明度 0.25。
- 路径橙色，宽 3px；已走节点实心，未走节点空心。
- 死胡同节点红色圆环，闪烁 1 秒。
- 目标节点画虚线圆表示邻域。
- 画布按 `devicePixelRatio` 缩放，避免模糊。

## 12. 性能

- 建图缓存键：`${n}|${alpha}|${k}|${seed}`，最多保留 8 张。
- Worker 单实例，批量结束后保留，下一次复用。
- 动画只重绘画布，不重建 DOM。
- 参数变化防抖 200ms，避免拖动滑块时反复建图。
- n 大于 128 时禁用并提示，首版上限 128。

## 13. 错误处理

- n 必须是 16 的倍数且在 16 到 128 之间，否则提示并回退到 32。
- s 与 t 相同时自动重抽。
- Worker 报错时状态置为 `error`，状态栏显示消息，结果表保留上次内容。
- 批量取消后清理进度条，不留下半截结果。

## 14. 验收标准

- 单次演示能切换 α、播放与单步，显示跳数与失败原因。
- 四个预设案例的行为符合上表预期。
- 批量能跑 n=16 到 64、α=0 到 3、graphs=5、pairs=20，一分钟内出表。
- 同一配置与种子，浏览器与 Node 的成功率与平均跳数一致。
- 导出的 CSV 能被绘图脚本直接读取。
